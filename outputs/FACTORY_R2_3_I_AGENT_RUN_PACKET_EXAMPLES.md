## ARP Usage Pattern

```
1. Factory runtime loads skills via skill-content-loader
2. Bridge generator creates ARP with skill summaries
3. ARP is output as JSON file in examples/agent-run-packets/
4. Real Codex session can consume ARP as context injection
5. Agent checks trustLevel and status before using skills
6. Handoff records skill usage in ledger
```

## Limitations

- ARPs are generated by Factory PowerShell scripts — not by live Codex agent
- Skill summaries are truncated to 500 chars — may lose nuance
- No real-time sync between ARP generation and Codex session
- Bridge is one-way: Factory → Codex, not bidirectional
