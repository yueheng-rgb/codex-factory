# FACTORY R2.3-D Bootstrap Capability Plan

## Overview

The Bootstrap Capability Plan is generated by `runtime/bootstrap-capability-plan.ps1` and integrates with the Factory Bootstrap flow. It produces a per-project/per-phase JSON plan that partitions all applicable capabilities into governance buckets.

## Inputs

| Parameter | Type | Description |
|-----------|------|-------------|
| projectId | string | Unique project identifier |
| phaseId | string | Phase identifier (PHASE-DESIGN, PHASE-IMPL-FE, etc.) |
| projectType | string | One of: content-site, fullstack-admin, saas-tool, api-service, miniapp, mobile-app, threejs-interactive |
| activeAgents | string[] | Agent IDs active in this phase (default: all 11) |
| localFirst | bool | Local-first constraint (default: true) |
| networkAllowed | bool | Network access permitted (default: true) |
| cloudAllowed | bool | Cloud services permitted (default: false) |
| secretsAllowed | bool | Auth/secrets configured (default: false) |
| sandboxAvailable | bool | Sandbox environment available (default: false) |
| humanApprovalAvailable | bool | Human confirmation available (default: false) |

```json
  "blockedCapabilities": [ ... ],

```

## Decision Flow

1. Filter all 91 registry entries by `projectType` match → projectCapabilities
2. For each `activeAgent`, filter by `applicableAgents` match → agentCapabilities
3. For each capability in agentCapabilities, run through 14-check Permission Gate
4. Partition gate result into one of 6 buckets: allowed, monitorOnly, blocked, pendingHuman, pendingSandbox, rejected
5. Log every gate decision to `capability-decision-index.jsonl`
6. Generate recommendedNextAction based on bucket contents

## Usage in Factory Bootstrap

```
. .\runtime\bootstrap-capability-plan.ps1
$plan = New-CapabilityPlan -ProjectId "PROJ-001" -PhaseId "PHASE-DESIGN" -ProjectType "fullstack-admin" `
  -ActiveAgents @("PM-001","ARCH-001") -LocalFirst $true
```

## Example: fullstack-admin design phase (PM+ARCH)

- 20 capabilities in scope
- 13 allowed (low-risk templates, verifiers, CLI tools, SDKs)
- 5 monitor_only (community search, external MCPs)
- 2 rejected (cloud services in local-first mode, secrets-required without auth)
- 1 pending_human (CAP-SKILL-099, AVAILABLE trust community skill)

## File Location

`governance/capability-plans/{projectId}-{phaseId}-capability-plan.json`
