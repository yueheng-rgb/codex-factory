## Accepted (4)

These recommendations are considered safe and beneficial:

1. **Hard Gate Dashboard**: Display all hard gates and status during a run.
2. **Pre-Flight Checklist**: Validate evidence before task submission.
3. **Test File Observer**: Parse test stdout to verify declared tests ran.
4. **Evidence Filing Protocol**: Standardize directory structure (docs/, scripts/, tests/, run/, reports/, command-logs/, evidence/).

---

## Rejected (2)

These recommendations were rejected because they would undermine the purpose of guardrails:

5. **Auto-Correction of Evidence**: Evidence must not be silently patched. Gaps must be surfaced.
6. **Self-Grading Run**: The verdict must be generated by the `finalize-run-verdict.ps1` script and archived independently of the report.

---

## Needs Human Review (3)

These recommendations have non-trivial trade-offs:

7. **Parallel Builder Verification**: Would slow down runs but strengthen isolation.
8. **Cross-Phase Evidence Chain**: Valuable for long projects but adds complexity.
9. **Runtime Guardrail Injection**: Would prevent submission of invalid evidence but may conflict with builder autonomy patterns.
