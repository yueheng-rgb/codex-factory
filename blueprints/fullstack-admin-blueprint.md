# Fullstack Admin Blueprint

## 用户需求拆解

当用户说"做一个 XX 管理系统"时，按以下步骤拆解：

### 最少必要问题（开工前必须搞清楚）
1. 管理什么数据？（核心实体是什么）
2. 谁在用？（管理员 / 普通员工 / 审核员？需要哪些角色？）
3. 注册开放吗？（默认不开，管理员手动创建账号）
4. 数据量多大？（决定要不要分页、搜索、导出）
5. 有没有审核/审批流程？

### 不能默认乱加的内容
- ❌ 不要默认加复杂的审批工作流
- ❌ 不要默认加数据导出/导入
- ❌ 不要默认加消息通知
- ❌ 不要默认加操作日志（除非需要审计）
- ❌ 不要默认加多语言
- ❌ 不要默认加富文本编辑器

## 第一版页面结构

```
/login          →  登录页
/dashboard      →  仪表盘（简单统计卡片：总数、今日新增等）
/[resource]     →  XX管理列表页（表格 + 分页 + 搜索 + 新建按钮）
/[resource]/new →  新建页（表单 + 校验）
/[resource]/[id]→  编辑页（表单回填 + 校验）
```

**不需要做的页面（第一版）：**
- 用户管理（除非明确需要）
- 角色管理（如果只有一种角色就不需要）
- 系统设置
- 操作日志

## 第一版数据结构

```
核心资源表
  id (PK)
  name / title
  status (active/inactive 等)
  其他业务字段
  created_by (FK → users)
  created_at
  updated_at

users
  id (PK)
  username
  password_hash
  role (admin / user)
  is_active
  created_at
  updated_at
```

## 第一版交互流程

```
用户打开系统
  → 未登录 → 跳转 /login
  → 已登录 → 跳转 /dashboard
  → 点击左侧菜单进入 XX管理
  → 看到数据表格（带分页）
  → 可以搜索/筛选
  → 点击"新建" → 弹出或跳转表单页 → 填写 → 提交
  → 成功 → 回到列表（列表自动刷新）
  → 失败 → 留在表单页，显示错误信息
  → 点击某行 → 跳转编辑页 → 修改 → 提交
  → 点击删除 → 确认弹窗 → 确认 → 列表刷新
```

## 第一版运行方式

```bash
npm install
cp .env.example .env       # 修改数据库连接
npx prisma migrate dev     # 创建数据表
npx prisma db seed         # 填充种子数据（可选）
npm run dev                # 启动开发服务器
```
