# Summary Verification Policy

## Problem
Compressed conversation summaries are auto-generated by Codex. They may:
- Omit critical details
- Invent or distort facts
- Present opinions as facts
- Lose context across long sessions

## Verification Rules
1. **No summary claim is accepted as evidence.**
2. **Every summary claim must be backed by an evidence path** (file hash, verifier result, agent handoff).
3. **If summary says "PASS" but verifier result says otherwise → verifier wins.**
4. **If summary and verifier agree → mark as L4 (cross-verified).**
5. **If summary has no backing evidence → mark as L0, navigation only.**
6. **Phase handoff must include summary + evidence cross-check.**

## Verification Process
1. Extract claims from summary (e.g., "60/60 PASS")
2. Locate evidence source (verifier JSON, file hash, test output)
3. Compare: claim == evidence? → YES: verified / NO: flag contradiction
4. Record verification result in context packet
5. If contradiction found → escalate to diagnostic gate

## BUILD-8 Example
- Summary: "29/29 PASS"
- Evidence: verifier JSON = total 29, passed 29, failed 0
- Result: VERIFIED. Level L4.
